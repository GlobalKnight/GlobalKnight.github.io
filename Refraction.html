Refraction

Refraction is a 2D light-based puzzle game with main mechanics including a flashlight revolving around the player and manipulating mirrors to eventually bring light back to the world. This project was made using a custom C++ engine heavily focused on manipulating individual pixels on a user's screen. This meant our graphics programmer used CPU rendering, which was intertwined and followed by GPU rendering to lighten the burden on the CPU. This limitation led to creative solutions from our engineers and helped create a unique atmosphere for our project going forward.

Gameplay Programming

Since I had designed the entity framework, I had a good understanding of how to create their own specific behaviors. This was done by creating behavior components specific to them as a way to do it without a way to incorporate scripting in our engine, so their unique behavior is inherited from the base behavior class. The features I implemented are behaviors for interacting with mirrors to move them along an array of points, doors for triggering level switches, and parts of the player and collision between some types of entities.

Technical Lead

Along with Refraction being my first interdisciplinary team, working on this project was also my first time ever in any kind of leading role on a team. It required me to work on skills I hadn't practiced before. I kept up quality standards and ensured tech and design were consistently aligned. This interdisciplinary practice allowed me to gain a deeper understanding of what it takes to bridge the gap between engineers and designers. Having taken the role alongside another team member, I focused on communicating and explaining what designers were expecting, including discussions centered around what we could do to engineer them. On top of communication, I led the team to ensure the game build was in a consistent working state by managing merge requests, then approving them to ensure they wouldn’t break the engine or current build.

Engine Programming

Within the engine, I wrote the game entity code and used a design like standard Entity Component Systems. Using examples and techniques I learned in my first game implementation class, I created a dynamic way to attach any number of components to any entity to make them their own.

	}

Later, after the engine had gotten on its feet more, I learned how to use .json to ensure that all our engine was data driven. I wrote systems for building each game level using .json files. I separated them into a few tasks: reading the level file, reading in and generating the tilemap, and then reading in and generating the entity list. Some problems that arose came from how to read in new parts and make sure that the files were aligned with what the designers worked with inside Tiled.

Designer Tools Programming

We implemented our engine using Dear IMGui for designer tools, enabling more real-time editing. I used it to create tools for importing and exporting the .json level files and helped design the framework for exporting game entities as well.

  void FileIO::ExportTileMap(std::string name)
  {
    Renderer* pixel = Renderer::GetInstance();
    int rows = static_cast(pixel->tileMapSize.x);
    int columns = (int)pixel->tileMapSize.y;

    std::vector tilemap;
    std::vector walls;
    bool found = false;
    for (int i = 0; i < columns; ++i) 
    {
      for (int j = 0; j < rows; ++j)
      {
        tilemap.push_back(pixel->tileMap[j][i] + 1);
        for (int k = 0; k < NUM_NON_WALKABLE_TILES; ++k)
        {
          if (pixel->tileMap[j][i] == pixel->nonWalkableTiles[k])
          {
            found = true;
            walls.push_back(pixel->tileMap[j][i]);
          }
        }
        if (found == false)
        {
          walls.push_back(0);
        }
        else
          found = false;
      }
    }

    json tilemapArray;
    json tilemapData;
    json name1;
    json name2;
    json tilemapCol; //collideables
    
    tilemapArray["width"] = rows;
    tilemapArray["height"] = columns;
    
    tilemapData["width"] = rows;
    tilemapData["height"] = columns;

    tilemapCol["width"] = rows;
    tilemapCol["height"] = columns;
    
    // seperated in two for easier collision flags for tiles
    tilemapData["name"] = "TileMap";
    tilemapCol["name"] = "Walls";

    tilemapData["data"] = tilemap;
    tilemapCol["data"] = walls;

    tilemapArray["layers"][0] = tilemapData;
    tilemapArray["layers"][1] = tilemapCol;

    // save tilemap to a file
    std::ofstream file("./Data/Scenes/" + name + "MAP" + ".json");
    file << std::setw(2) << tilemapArray << std::endl;

    json readable;
    json data;
    data["TileMapFile"] = "./Data/Scenes/" + name + "MAP" + ".json";
    readable["TiledData"] = data;

    //the filemap to read
    std::ofstream actualfile("./Data/Scenes/" + name + ".json");
    actualfile << std::setw(2) << readable << std::endl;
  }
